# 单据编号

统一格式：`前缀 + yyyyMMdd + 3 位流水号`，无分隔符。

| 单据 | 前缀 | 日期来源 | 示例 |
| --- | --- | --- | --- |
| 销售订单 | SO | order_time | SO20261018001 |
| 采购订单 | GL | order_time | GL20261018001 |
| 入库单 | IN | inbound_time | IN20261018001 |
| 出库单 | OUT | outbound_time | OUT20261018001 |

按类型、业务日期独立递增，从 001 开始，超过 999 明确拒绝。业务日期为空的历史单据使用创建日期，SQL 统一在北京时间下转换 timestamp。

后端 `DocumentNumberService` 在单据事务内锁定 `document_number_sequence` 对应行，同时检查已落库编号的最大流水。流水与单据一同提交或回滚。已有单据更新不重新编号，库存 BAT 批次规则不变。

已有数据库：停止应用写入、备份后执行 `migrate_document_numbers.sql`，再启动新版后端。旧入库结构须先按 `inbound_many_to_many.md` 完成关系迁移和历史包裹合并。迁移保留符合规则的现有单号，对不符合规则的历史记录按业务日期、同日 ID 顺序分配新号；同步采购明细、入库明细、入库批次和关联表中的采购单号。可重复执行，不改变客户采购单号、ID、数量、成本和库存批次。

全新数据库：执行 `glw.sql` 和 `full_data.sql`，全量数据已经使用新编号并初始化流水。

销售订单、采购订单与销售出库现有前端新增流程仍使用浏览器本地保存，生成编号也遵循同一规则；它们不具备服务器跨用户的流水协调能力。采购入库通过真实后端创建，由数据库分配正式单号。
