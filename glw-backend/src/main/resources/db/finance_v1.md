# 财务第一版

日常页面操作步骤见 [财务模块操作手册](../../../../docs/finance-user-guide.md)。

## 代码分层

财务表分别提供 `model/entity/Fin*`、`mapper/Fin*Mapper`、对应 XML，以及 `service/Finance*Service` 接口和 `service/impl/Finance*ServiceImpl` 实现，沿用 MyBatis-Plus 的 `BaseMapper`、`IService`、`ServiceImpl`。

应收应付投影、对账单、收付款、核销、结算档案、审计和事务锁按职责拆分。自定义 SQL 全部放在各自 Mapper XML 中，包括订单付款状态的计算和筛选；Java 不使用 SQL 注解或 SQL Provider。财务建表已并入 `glw.sql`，不再单独维护 `finance.sql`。

## 初始化

开发阶段只维护两个脚本：`glw.sql`（全部表结构，含财务 `fin_*`）和 `full_data.sql`（全部数据）。先后执行这两个文件即可得到完整数据库，不维护增量脚本。

表结构或数据有变动时，直接覆盖这两个文件，然后删除原库重新执行；已有库不要在上面对增量操作。财务表重建后是空的，财务记录由应用按业务单据生成。

`full_data.sql` 里的 25 张已完成出库单已带客户签收日期（暂无真实回签单据，统一按出库次日登记，仅用于演示与验证账单月计算）；重建并历史回填后应收即可直接出单。实际业务按真实回签日期在出库单上登记。

在“财务管理 → 结算档案”设置客户／供应商的截止日、账单周期、出单日与到期规则，再由管理员在“应收应付”执行“历史回填”。未设置档案时按自然月出单、未配置账期则到期日等于账单期末。账单月、期间、到期日在投影与签收时按当时档案计算并固化，修改档案不会追溯修改已入库的记录和已出账单。

## 已实现

- 财务表独立：可对账项、对账单及其快照明细、收付款、核销、结算档案、审计记录。
- 仅 CNY；入库、出库完成，在同一业务事务内按每条订单分配行生成 AP、AR。
- 历史回填只补缺失，不覆盖已有价格、税率、到期日、核销和对账记录。
- 数量、单价、金额、币种来自出入库分配行快照，不能重新读取订单现价，也不使用库存成本替代采购价。
- 金额字段统一 `decimal(12,4)`、四位小数，HALF_UP。未税金额加税，含税金额拆税；含税且税率未知时价税合计可用，未税金额和税额为空。
- 未税报价未填税率时视为不含税交易：价税合计等于未税金额，不额外加税，可直接对账。客户不加税、不开票的业务保持税率为空即可。
- 采购订单按含税单价计价、税率 13%：应付的价税合计取订单含税金额，未税金额按含税金额除以 1.13 反算，税额为差额，供毛利和进项核算。销售未税报价不加税，采购含税 13%，两个方向口径独立。
- 每条对账项整体纳入一张有效对账单；同单位同月份允许多张补充对账单。可对账项跨单位、跨方向、跨月份、跨币种不能混在一张单。
- 对账单：草稿 → 已发送 → 已确认；草稿、已发送可以作废并释放对账项，已确认不能直接作废或改价。导出后端生成 CSV，Excel 可打开。
- 收付款可以在对账前登记，余额保持未分配；对账确认后才允许核销，支持一款多项、一项多款以及部分核销。
- 核销必须同方向、同单位、同币种，不能超过收付款未分配余额或应收应付未结金额。
- 反核销恢复双方余额，保留原核销记录；有有效核销的收付款不能作废。收付款及核销请求标识防止重复记账。
- 账单月按客户档案的截止日切分：基准日在 C 日（含）之前归当月，之后归下月；未配置截止日按自然月。账单期间为 (M-1) 月 C+1 日到 M 月 C 日，跨月周期取首月起点到末月终点。
- 账单周期 `cycle_months` 从最早一条记录的账单月起算覆盖 N 个月，超出窗口的记录从它自己的账单月起重新起算；中间没有记录的月份直接跳过，不补出空账单。出单月 = 账单结束月 + `statement_lag_months`，出单日 = `statement_day`（超出月长取月末）。出单日必须晚于账单期末：自然月、截止 31 日的档案只允许次月及以后出单，截止 1–30 日时当月出单要求出单日大于截止日；保存档案时按 `BillingCalendar.profileProblem` 校验。
- 到期日支持两种规则：固定天数（从账单期末、出单日或出单月末起算 `credit_days`），或约定日历日（账单结束月 + `due_month_offset` 月的 `due_day`，`due_day=0` 表示月末）。约定付款月不能早于出单月，同月时约定日还要晚于出单日。出单时明细的到期日对齐到账单到期日，保证一张对账单内口径一致。
- AR 以出库单签收日期为对账基准日：未签收的记录标记待签收，账单月、期间、到期日为空，不参与出单预览和自动出单；登记签收后在事务内重算。AP 以入库日期为基准，入库完成即可对账。签收时间不得早于出库时间。
- 手工出单可一次勾选多条记录；跨多个账单周期时按周期拆成多张对账单返回。自动出单任务只处理“期间已结束、已签收／已入库、未对账、未进入任何对账单”的记录，生成草稿，不补历史缺口；执行时间为 `app.finance.auto-statement-cron`（默认每日 01:40），管理员也可手工触发 `POST /api/fin/statement/auto-generate`。
- 销售、采购订单列表及付款状态筛选，在存在财务投影后读取财务核销结果，不改写原业务状态。尚未全部交货的订单，即便已交部分结清，也按部分收付款展示。
- 所有财务写操作使用事务和统一数据库行锁；第一版适用于小公司低并发，来源唯一键额外防重复。财务单号使用现有事务内每日编号机制：AR、AP、RC（收款）、PY（付款）。
- 操作日志记录当前用户、时间和操作；历史回填仅 ADMIN，其他操作沿用现有登录权限。

## 历史金额边界

`full_data.sql` 中的“已收款／已付款”状态并不包含银行到账记录、具体金额和核销关系，不能据此虚构收付款单。历史回填只生成交易应收应付，未结金额指**当前财务账中尚未核销的金额**。历史实际已结款的部分，需要按真实凭据登记、对账并核销后才会反映；不能直接将这批初始未核销金额当成客户实际欠款。

系统不猜测税率。未填税率的记录按报价金额记应收应付，税额为空，价税合计与未结金额照常汇总；需要拆出未税和税额时，应在订单行录入税率。

## 暂不包含

发票及红冲、折让尾差、退换货调整、外币、签收单回签附件上传、关账、银行导入。第一版不支持修改已确认金额；存在这些业务时应先补对应调整流程。
