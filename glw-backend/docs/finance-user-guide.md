# 财务模块操作手册

适用于当前第一版页面。菜单入口为“财务管理”，包含应收应付、对账单、收付款、结算档案。

## 一、先理解这几个概念

| 页面或操作 | 含义 |
| --- | --- |
| 应收 / 客户 | 已完成出库所形成的应收金额 |
| 应付 / 供应商 | 已完成入库所形成的应付金额 |
| 对账单 | 把同一单位、同一月份的交易整理成一份清单，供双方核对 |
| 登记收款 / 登记付款 | 记录已经实际发生的资金收付，不会代替银行转账 |
| 核销 | 把已登记的收付款分配到具体交易，减少其未结金额 |
| 反核销 | 撤销一笔金额分配，恢复双方余额，不代表银行退款 |
| 结算档案 | 设置客户或供应商的账期，供后续计算到期日 |

采购或销售下单本身不会生成这里的应收应付。完成入库、出库后，系统才按实际数量和业务价格生成记录。部分交货只生成已交部分的金额。

一次出入库分配给多个订单时，会按订单分配明细生成财务记录；同一订单分批交货，也会有多条财务记录。

## 二、首次使用

### 1. 设置结算档案

1. 打开“财务管理 → 结算档案”。
2. 选择上方“应收 / 客户”或“应付 / 供应商”。
3. 点击“添加档案”，选择客户或供应商。
4. 选择“账期起算”，填写“账期天数”，保存。

例如，选择“出入库日期”、30 天，10 月 10 日的交易到期日为 11 月 9 日；选择“业务当月月底”、30 天，同一笔交易到期日为 11 月 30 日。

没有档案时，到期日默认为出入库日期。账期只在财务记录首次生成时计算，后续修改档案不会改变已经生成的到期日。

### 2. 补齐历史交易

1. 使用管理员账号打开“财务管理 → 应收应付”。
2. 点击“历史回填”，确认操作。
3. 分别查看客户应收和供应商应付。

历史回填会补齐已完成入库、出库的缺失财务记录，已有记录不会重建。重复点击不会重复记账，也不会重新计算已有记录的账期。

本地此前已经进行过历史回填，不需要为了日常使用重新初始化数据库。新完成的出入库会自动生成财务记录。

### 3. 处理税率待确认记录

1. 在“应收应付”筛选状态“税率待确认”。
2. 点击记录的“确认税率”。
3. 根据真实合同或交易凭据填写税率，例如 13 表示 13%，确认。

未税报价且税率缺失时，系统不能确定最终应收应付金额，该记录暂不参与对账和核销，也不计入价税合计、未结金额及逾期汇总。不要为了通过校验随意填 0。

含税报价但税率未知时，含税总金额已确定，可以对账；未税金额和税额暂时为空。

## 三、每月生成并确认对账单

以客户销售对账为例：

1. 打开“财务管理 → 应收应付”，选择“应收 / 客户”。
2. 筛选客户和月份。这里的月份取实际出库日期所属月份，不是销售下单月份。
3. 核对明细、数量、价格和金额。
4. 不勾选明细时，点击“按筛选生成对账单”，系统读取当前筛选范围内全部待对账记录，包含其他分页。若只需部分记录，先勾选，再点击“生成对账单”。
5. 在预览弹窗中检查内容，填写备注，点击“生成草稿”。
6. 打开“财务管理 → 对账单”，点击对应单号进入详情，导出文件。
7. 自行通过微信、邮件等方式发给客户，再点击“标记已发送”。此按钮只更新系统状态，不会自动发送文件。
8. 客户核对并确认无误后，点击“确认对账”。

供应商对账采用相同步骤，切换为“应付 / 供应商”即可，月份取实际入库日期所属月份。

一张对账单只能包含同方向、同单位、同月份、同币种的记录，最多 1000 条。已经纳入有效对账单的交易不能重复生成；同单位同月份后来补入的交易，可以另生成补充对账单。

状态顺序为：草稿 → 已发送 → 已确认。只有已确认对账的交易才能核销。

## 四、登记实际收款或付款

1. 打开“财务管理 → 收付款”。
2. 客户到账选择“应收 / 客户”，点击“登记收款”；向供应商付款选择“应付 / 供应商”，点击“登记付款”。
3. 选择往来单位，填写实际收付款日期和实际金额。
4. 根据需要填写银行流水号、备注，点击“保存”。

日期填写资金实际发生日期，不必与对账月份一致。银行流水号、备注不是必填项，但可以用于后续查找凭据。

保存只表示登记了这笔钱，尚未对应具体交易，因此初始显示“未核销”。同一笔真实到账或付款只登记一次，不要因为覆盖多个订单而重复登记全额。

可以先登记收付款，等对账确认后再核销。

## 五、将收付款核销到具体交易

1. 在“收付款”列表点击对应收付款单号，打开详情。新登记成功后也会打开详情。
2. 在“待核销应收应付”中找到要结算的交易。
3. 点击该行“核销”，填写本次分配给这条交易的金额。
4. 点击“确认核销”。
5. 如果这笔钱对应多条交易，继续逐条分配。

待核销列表只显示同一客户或供应商、同方向、已确认对账且尚未结清的交易。暂时看不到交易时，先检查对账单是否已“确认对账”、是否选错往来单位，以及是否还有其他分页。

每次核销金额不能超过收付款的未分配余额，也不能超过该条交易的未结金额。一笔钱可以核销多条交易，一条交易也可以分多次收付款核销。

例如，客户有两条已确认交易，分别为 1000 元和 2000 元，实际到账 2500 元：

1. 登记一笔 2500 元收款。
2. 对第一条交易核销 1000 元。
3. 对第二条交易核销 1500 元。

结果是：该收款已全部核销，未分配余额为 0；两条交易累计已结 2500 元，第二条还剩 500 元未结。以后再收到 500 元，登记新收款，再核销到第二条交易。

收付款显示“已核销”，只代表这笔钱分配完毕，不代表该客户或供应商的全部交易已经结清。

## 六、查看余额和逾期

在“应收应付”选择方向，并按单位、月份等条件筛选：

| 指标 | 查看内容 |
| --- | --- |
| 价税合计 | 当前筛选范围内已确定的含税交易金额 |
| 已结金额 | 已经通过核销分配到这些交易的金额 |
| 未结金额 | 含税交易金额减去已核销金额 |
| 逾期未结 | 到期日已过且尚未核销的金额 |
| 未分配收付款 | 对应方向、单位和收付款月份范围内，还没有分配到交易的资金余额 |

交易月份与收付款月份可以不同，不能在只筛选某个月时，简单用“未结金额减未分配收付款”认定最终欠款。

历史基础数据中原有的“已付款 / 已收款”状态，没有具体银行收付和核销明细，系统不会凭该状态虚构资金记录。历史已结款部分需要根据真实凭据补录收付款并核销；补录完成前，页面未结金额不能直接当成对方实际欠款。补录历史款项时注意避免与已登记收付款重复。

## 七、录错后的处理

### 对账单选错明细或内容有误

草稿、已发送状态可以在详情中点击“作废”，原交易会释放，重新选择生成。已确认对账单当前不支持直接作废或改价，确认前务必核对。

### 核销分配错了

打开“收付款”详情，在“核销记录”中对错误记录点击“反核销”。对应交易恢复未结金额，收付款恢复未分配余额，再重新分配。原核销记录保留为“已反核销”。

### 收付款单位、金额或日期录错了

先反核销该单全部有效核销记录，再点击“作废”，然后按真实凭据重新登记。已经核销的收付款不能直接作废。

## 八、建议的日常顺序

1. 业务完成入库、出库，系统自动生成应付、应收。
2. 每月按单位整理对账单，导出并发送。
3. 对方确认后，在系统确认对账。
4. 按实际资金流水登记收付款。
5. 将收付款核销到对应交易。
6. 检查未结、逾期以及未分配余额。

当前版本仅支持人民币，暂不包含发票、红冲、退款、退换货调整、尾差折让、自动发送及银行流水导入。
